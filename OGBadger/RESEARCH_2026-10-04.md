# OGBadger research — 2026-10-04

## Confirmed / strong evidence

### Xbox-side telemetry is technically realistic
XbDiag is a native RXDK application for OG Xbox revisions 1.0–1.6 and reports CPU/board temperatures, fan data, HDD identity/capacity, RAM, BIOS, network and other hardware information. It specifically handles rev 1.6 temperature monitoring via the PIC/Xcalibur path. This strongly supports the feasibility of an OGBadger XBE reading useful telemetry. Source: https://github.com/Darkone83/XbDiag

### Cerbios supports the intended development environment
Cerbios currently supports Xbox 1.0–1.6b. Its published features include custom fan speed control and external boot animations. This makes a Cerbios 1.6 development machine a sensible target, while keeping the Badger XBE independent of Cerbios-specific features where possible. Source: https://github.com/Cerbios/Cerbios-Xbox

### DVD connector is a good power tap
The OG Xbox DVD connector carries +12 V, +5 V and ground, plus DVD activity/tray signals. The power rails are suitable candidates for an inline Badger power adapter, but actual Badger current requirements and connector mating parts still need engineering validation. Source: Xbox Hardware Reference / Hacking the Xbox, Appendix F.

### Important revision consideration
Xbox power connector pinouts differ across motherboard revisions, including 1.6. Therefore the proposed DVD inline adapter should be based on the DVD connector itself, not the main PSU connector, and its exact mating connector/wiring must be verified for all revisions we intend to support.

## Architecture implication

Preferred stock path:
Xbox DVD power -> inline Badger adapter -> ESP32-S3 -> round LCD.

Preferred modded path:
Xbox XBE -> local network discovery/protocol -> ESP32-S3.

Avoid electrical data tapping of the Xbox motherboard for the consumer product unless later research demonstrates a compelling reason.

## Immediate technical experiments

1. Obtain the proposed Cerbios 1.6 development Xbox.
2. Run XbDiag and record exactly which telemetry is available.
3. Establish the simplest possible XBE -> network message.
4. Establish ESP32-S3 network discovery/receive test.
5. Define a tiny OGBadger telemetry packet.
6. Test round-display candidates around the required image diameter and interface.
7. Build/verify a reversible DVD inline power adapter.
8. Only then design the production interconnect/PCB.

## Display warning

Do not assume that every round 480x480 display is SPI pixel-driven. Some round 480x480 modules use controllers such as ST7701S with a serial command interface but RGB/parallel pixel transport. These may require substantially more ESP32-S3 GPIO and a different driver architecture. Existing GC9B72-style SPI experience is therefore valuable, but display selection must be based on the actual module interface.

## Open questions

- Exact best round LCD at/near 67.28 mm image diameter.
- Whether 480x480 is worthwhile versus lower-resolution SPI displays.
- Universal lid/jewel fit across Xbox revisions.
- Exact DVD inline connector part.
- Maximum safe current draw from DVD +5 V / +12 V rails.
- Network discovery method that requires zero customer configuration.
- XBE development toolchain and runtime environment.
- Which telemetry can be read reliably without Cerbios-specific assumptions.
- Custom animation package size/compression.
- Microsoft IP/trademark/copyright implications of shipping Xbox-style default animation/assets.

## Evidence rule

The XbDiag project proves that the underlying telemetry access exists. It does NOT yet prove that our own XBE can reproduce every required value, nor that every modded Xbox environment will behave identically. Those are development tests.
